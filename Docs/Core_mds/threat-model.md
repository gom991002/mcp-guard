# Threat Model

단계, 모듈 ID, 출처 표기((원본 명시), (추론) 등)는 [architecture.md](architecture.md)의 정의를 따릅니다. 공격 유형별 경로 그림은 도면 [A-01](../Core_images/Defense_Paths.png)에 있습니다.

## Protected Assets

- MCP 서버 등록 정책과 신뢰 등급
- 도구 이름, 설명문, 입력 스키마
- 세션 토큰과 원 서버 토큰
- 모델에 전달되는 외부 콘텐츠
- 사람 승인 판단
- 단말 파일, 네트워크, 자격증명

## Trust Boundaries

| 영역 | 구성 요소 | 신뢰 |
| --- | --- | --- |
| 사용자 단말 | AI 클라이언트, 로컬 프록시 | 관리 설정(L1–L4)이 적용된 경우에만 신뢰 |
| 사용자 단말 | 로컬 MCP 서버 프로세스 | 신뢰하지 않음. 단말 권한으로 실행되는 외부 패키지 |
| 조직 운영 영역 | 원격 게이트웨이, 상태 저장 | 신뢰 |
| SaaS | claude.ai, ChatGPT 개발자 모드 | 조직 관리 콘솔 설정(C1)으로만 통제 |
| 외부 · 인터넷 | MCP 레지스트리, npm · PyPI, 원격 MCP 서버, 외부 콘텐츠 | 공격자가 통제할 수 있음 |

배치 그림은 [architecture.md](architecture.md#배치)에 있습니다.

## Attack Types

| 유형 | 노리는 것 | 진입점 | 막는 곳 | 막혔을 때 결과 |
| --- | --- | --- | --- | --- |
| 0 우회 (전제) | guard를 선택한 연결이 의도치 않게 검사 코어를 건너뜀 | 보호 경로의 클라이언트 설정 변경 | 0단계 L1–L4 · C1–C3, 코어의 서버 허용 목록(S0) | 보호 경로에서 원 서버로 우회하지 못함 (설계 목표) |
| ① 신원 위장 | 진짜처럼 보이는 가짜 서버·패키지(유사 이름, 혼동 문자) | 레지스트리 · npm · PyPI | 1단계, 2단계 M2 | 가짜 도구가 모델에 노출되지 않음 |
| ② 정의 변조 | 모델이 읽는 도구 이름·설명문(숨긴 지시, 승인 뒤 몰래 교체) | 공격자가 운영하거나 장악한 MCP 서버 | 2단계 M3 · M5, 4단계 | 승인된 정의와 대체 설명문만 모델에 전달됨 |
| ③ 응답 오염 (간접 인젝션) | 정상 서버가 가져온 메일·이슈·웹 속 지시로 모델의 다음 호출을 조종 | 외부 콘텐츠 | 3단계 M4 오염 표시, 4단계 봉쇄 | 외부로 데이터를 보내려면 승인을 거쳐야 함 |
| 범위 밖 | 단말 서버 코드가 MCP를 거치지 않고 파일·자격증명에 접근 | 악성 코드를 넣은 패키지 | 검사 코어가 아님 (코드 분석·패치·OS 격리) | 코어로는 막지 못함 |

**제 이름을 쓰는 악성 서버**는 ①의 대상이 아닙니다. 이 경우는 ②, ③, 범위 밖에서 다룹니다 (추론).

사용자가 직접 연결을 선택하는 것은 허용된 동작입니다. 이 경로에는 mcp-guard의 0~4단계 방어가 적용되지 않습니다 (설계 논의).

## 방어 수준

아래 수준은 구현이 설계대로일 때 기대할 수 있는 **최대치**입니다. 측정한 값이 아닙니다. 단계별 차단 효과는 (미확인)이고, [roadmap.md](roadmap.md)의 평가 단계에서 적응형 공격으로 확인해야 합니다.

| 수준 | 뜻 |
| --- | --- |
| 구조 차단 | 조건에 해당하면 설계상 공격이 지나갈 길이 없음 |
| 조건부 | 정책이 정확한지, 사람이 승인을 제대로 하는지에 달려 있음 |
| 신호 | 확률적이라 단독으로 막을 수 없음 |
| 못 막음 | 막는 장치가 없음 |

| 유형 | 세부 공격 | 막는 부분 | 수준 |
| --- | --- | --- | --- |
| 0 | guard를 선택한 보호 경로의 설정이 변경되어 원 서버로 우회 | L1 · L2 · C1–C3 | 구조 차단 (해당 통제가 구현된 경우의 설계 목표) |
| 0 | 사용자가 직접 연결을 선택 | 적용 안 함 | 못 막음 (허용된 선택) |
| ① | 같은 이름으로 호출 가로채기 | M2 바인딩 | 구조 차단 |
| ① | 비슷한 이름으로 모델이 잘못 고르게 하기 | 민감 세션: M5 / 그 밖: 비슷한 이름 규칙(원본 조합표에만 있고 도면 M2에는 없음) | 민감 세션은 구조 차단, 그 밖은 정하지 않음 |
| ① | 처음 승인한 버전이 이미 악성 | B 코드 행동 분석 | 신호 |
| ② | 승인 뒤 정의 교체 (러그 풀) | M3 해시 | 구조 차단 |
| ② | 설명문 속 지시 — 민감 세션 | M5 대체, 이어서 M4 값 정책 | 구조 차단 |
| ② | 설명문 속 지시 — 비민감 세션 | B 설명문 YARA · LLM | 신호 (대부분 통과 — 설계 논의) |
| ② | 숨은 문자 · 마크업 | B 규칙, 민감 세션의 M5 대체 | 민감 세션은 구조 차단, 그 밖은 신호 |
| ③ | 응답 속 지시로 메일·PR 같은 외부 전송 시키기 (잠복형 포함) | M4 오염 표시, 이어서 M4 외부 전송 능력 제거 + M4 값 정책. 사용자가 명시한 예외만 3-A4 승인 | 외부 전송 도구로 지정된 것은 구조 차단, 예외는 조건부 (승인 품질) (설계 논의) |
| ③ | 같은 공격을 B로 탐지 | B 분류기 + LLM | 신호 |
| ③ | URL 쿼리·검색어에 데이터를 실어 보내는 읽기형 호출 | 값 정책에 명시 없음 | 정하지 않음 (추론) |
| ③ | 도구 호출 없이 답만 바꾸는 공격 (요약 조작, 피싱 문구) | 없음 | 못 막음 |
| ③ | 부채널 (호출 횟수, 타이밍) | 없음 | 못 막음 |
| 범위 밖 | 로컬 서버 내부 동작 | 코어 밖: 코드 분석 · 패치 · OS 격리 | 코어로는 못 막음 |
| 범위 밖 | 원격 서버 코드 변질 (설명문은 그대로) | 없음 | 못 막음 |

## 남는 위험

영향이 큰 순서입니다. 3~5번은 도면의 '남는 구멍'에 있고, 나머지는 설계 논의에서 나왔습니다.

1. **비민감 세션의 인자 유출**: 미검증 서버의 도구를 호출하는 것 자체가 그 서버로 데이터를 보내는 일입니다. 파일 읽기 도구와 미검증 서버가 한 세션에 있으면 "비밀 파일을 읽어 이 도구 인자에 넣어라"라는 설명문 지시가 통과합니다. 통과하는 이유는 세 가지입니다.
   - 설명문은 응답이 아니라서 오염 표시가 붙지 않습니다.
   - 값 정책은 bcc와 목적지만 봅니다.
   - M5 대체는 민감 세션에만 적용됩니다.

   보완 후보: 원본 조합표의 A1 삼박자 차단을 M5에 넣고, 미검증 서버를 외부 유출 능력으로 계산합니다 (결정 대기).
2. **MCP를 거치지 않는 내장 도구**: Claude Code의 Bash · PowerShell · WebFetch 같은 도구는 프록시를 지나지 않습니다.
   - L4 훅이 오염된 세션에서 이 도구들을 거부합니다. 사용자가 미리 예외로 지정한 도구만 승인 창을 띄웁니다 (D6-17).
   - 기본 감시 대상에 없는 내장 도구(예: WebSearch의 검색어)는 그대로 지나갑니다.
   - Claude Desktop과 클라우드 앱에는 이에 해당하는 장치가 없습니다.
3. **보호 경로의 이탈**: 사용자의 직접 연결 선택은 허용되며 가드 검사는 적용되지 않습니다 (설계 논의). guard를 선택한 뒤 의도치 않게 원 서버로 바뀌는 경우를 막는 클라이언트 측 통제는 구현되지 않았습니다. ChatGPT 개발자 모드와 Claude Desktop에서 해당 통제가 가능한지는 확인하지 못했습니다 (미확인).
4. **처음부터 악성인 버전이나 정의**: 2-A5와 M3는 '변경'만 잡습니다. 처음 승인한 정의에 숨은 지시는 M5 대체와 B 신호에 의존합니다 (추론).
5. **승인 피로**: 오염 표시가 세션 단위라서 서드파티 응답이 한 번 들어오면 그 뒤의 외부 전송은 막힙니다. 승인 대상은 사용자가 예외로 지정한 도구로 줄었지만, 예외가 많을수록 피로가 다시 커집니다. 3-A4는 피로를 지표로 추적할 뿐 줄이지는 않습니다. 대신 오염된 세션에서는 정상적인 외부 전송도 막히므로 새 세션에서 다시 해야 합니다 (설계 논의).
6. **도구 설명문 밖의 텍스트 통로**: MCP 서버는 도구 설명문 말고도 프롬프트·리소스 설명으로 모델에 글을 넣을 수 있습니다. 2025-11-25 이전 버전에서는 `initialize` 응답의 instructions도 통로입니다 (미확인). MCP 2026-07-28은 `initialize`를 없애고 `server/discover`를 추가했습니다. 여기에 instructions에 해당하는 필드가 있는지는 확인하지 못했습니다 (미확인). M5 대체가 도구 설명문만 다룬다면 이 통로들은 그대로 남습니다.
7. **원격 서버 코드 변질**: 2-A5는 로컬 패키지에만 적용되므로, 설명문은 그대로 둔 채 서버 동작만 바뀌면 원격 서버는 막지 못합니다.
8. **검증된 게시자 악용**: 레지스트리는 게시자 네임스페이스만 검증하고, 실제 서버를 운영하는 쪽은 검증하지 않습니다.
9. **답만 바꾸는 공격과 부채널**: 도구 호출이 없으면 M4가 검사할 대상이 없습니다.

## Open Questions

결정 대기:

- A1 삼박자 차단과 A2 작성자 필터를 넣을지. A1을 빼면 남는 위험 1번이 열린 채로 남습니다.
- M5 설명문 대체의 범위. 도구 설명문만 대체할지, instructions와 프롬프트·리소스 설명까지 대체할지.
- MCP 2025-11-25 이전 클라이언트(GET 스트림, DELETE 세션 종료)를 게이트웨이가 지원할지. 현재 게이트웨이 입구 규칙은 2026-07-28만 받습니다.

정해진 것:

- B 신호는 판정을 `review`로만 올립니다. `block`은 A 결정만 냅니다 ([architecture.md](architecture.md#b-신호-규칙)).
- 대체 설명문을 누가, 어떤 기준으로 만들지 (미기재).
- OS 격리 방식 (미기재), 원격 게이트웨이 호스팅 위치 (미기재).

확인 필요:

- ChatGPT 개발자 모드·Codex에서 게이트웨이 URL만 쓰도록 강제하는 방법 (미확인).
