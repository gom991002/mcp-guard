# 11 B Classifier

MVP 열한 번째 작업 구역입니다. Horizon Labs Prompt Injection Guard small을 선택형 B 신호로 사용합니다. 게이트웨이는 `--b-classifier`를 지정할 때만 이 폴더를 불러옵니다. 도구 설명문 점수는 등록 판정을 최대 `review`까지 올리고, 도구 응답 점수는 `response_classified` 감사 이벤트로만 남깁니다. 응답 내용은 변경하지 않습니다.

B 설명문 문구·구조·LLM 검사 평가 코드와 결과는 [b_text/README.md](b_text/README.md)에 있습니다.

| 파일 | 하는 일 |
| --- | --- |
| [b_classifier/prompt_guard.py](b_classifier/prompt_guard.py) | 고정된 Horizon 모델 리비전의 양자화 ONNX 가중치를 불러와 INJECTION 확률(0~1)을 계산합니다. 긴 글은 2048토큰 창과 512토큰 겹침으로 검사합니다 |
| [b_classifier/description_llm_client.py](b_classifier/description_llm_client.py) | 2단계 B 설명문 LLM 검사(D6-44, 선택, 기본 꺼짐)의 OpenAI 호환 클라이언트. 일반 http는 loopback이나 운영자가 적은 호스트에만 허용하고 리디렉션은 거부합니다. 게이트웨이 `--description-llm-url`과 로컬 매니페스트 `description_check`가 씁니다 |
| [b_classifier/evaluate.py](b_classifier/evaluate.py) | 언어별 탐지율, 오탐률, 놓친 항목, 처리 시간(중앙값·최대)을 냅니다 |
| [datasets/eval_ko_en.jsonl](datasets/eval_ko_en.jsonl) | MCP 모양의 평가 샘플 36개. 한국어 24개(공격 12, 정상 12), 영어 12개(공격 6, 정상 6). 공격은 직접 지시 무시, 도구 설명문 속 유출 지시, 도구 응답 속 간접 지시, 역할극 탈옥, 공손한 덮어쓰기, 한영 혼합, 띄어쓰기 우회. 정상은 설명문, 응답, 지시처럼 보이는 정상 문장, 보안 설명 |

평가 세트는 직접 쓴 소량의 확인용이라 벤치마크가 아닙니다. 수치는 "한국어에서 동작하는가"를 보는 첫 신호로만 씁니다.

## 실행

1. 선택형 패키지를 설치합니다: `pip install -e ".[classifier]"`. 모델은 [Horizon 모델 페이지](https://huggingface.co/Horizon-Labs/prompt-injection-guard-small)에서 처음 실행할 때 받습니다. 가중치는 저장소에 포함하지 않습니다.
2. 게이트웨이를 `--b-classifier --b-threshold 0.5`로 실행합니다. 기존 인자와 서버 승인 설정도 필요합니다. Docker에서는 `deploy/.env`에 `MCP_GUARD_WITH_CLASSIFIER=1`과 `MCP_GUARD_B_CLASSIFIER=1`을 넣고 이미지를 다시 빌드합니다. 가중치는 `/data/hf-cache`에 저장됩니다.
3. 평가:

   ```powershell
   python mvp/11-b-classifier/b_classifier/evaluate.py --dataset mvp/11-b-classifier/datasets/eval_ko_en.jsonl --report b-eval.json
   ```

   테스트로도 돌릴 수 있습니다: `$env:MCP_GUARD_RUN_PROMPT_GUARD = "1"; python -m unittest tests.test_mvp11_b_classifier`

## 한국어 평가 세트 v2와 기준 (D6-50, 2026-11-04)

| 파일 | 하는 일 |
| --- | --- |
| [datasets/ko_eval_v2.jsonl](datasets/ko_eval_v2.jsonl) | 한국어 300개(공격 150, 정상 150). 공격 문장 50개(13종)를 정상 도구 설명문·응답에 세 가지 위치로 넣었고, 정상 150개 중 70개는 지시처럼 보이거나 공격을 설명하는 정상 문장(어려운 정상)입니다 |
| [datasets/make_ko_eval_v2.py](datasets/make_ko_eval_v2.py) | 위 파일을 만드는 스크립트. 테스트가 파일과 스크립트 결과가 같은지 확인합니다 |
| [b_classifier/cv.py](b_classifier/cv.py) | 정상 보류 2% 이하를 지키는 기준값 중 공격을 가장 많이 잡는 값을 고르고, 5겹 교차검증으로 성능을 냅니다. 같은 공격 문장은 한 겹에만 들어갑니다 |

- **출처와 검토:** 공개 데이터를 옮기지 않고 이 저장소용으로 AI(Claude)가 작성했습니다. MCPTox는 라이선스 표기가 없어 번역본도 넣지 않았습니다. 정답 표시는 작성자 기준이고 사람 검토는 보류 중입니다(`review: pending`). 한 작성자가 공격과 정상을 모두 썼으므로 실제보다 쉽거나 어려울 수 있습니다.
- **기준(결과를 보기 전에 정함):** 정상 보류 2% 이하(D6-44와 같은 기준), 그 안에서 탐지율 최대. 정상 150개 중 0개를 잘못 잡아도 95% 신뢰 상한은 약 2.5%(Wilson)라서, 이 세트로는 "2% 이하"를 겨우 확인할 수 있는 크기입니다.
- **실행:** `python mvp/11-b-classifier/b_classifier/evaluate.py --dataset mvp/11-b-classifier/datasets/ko_eval_v2.jsonl --cv --resources --report r.json` (모델 없이 규칙만: `--cv --rules-only`).

### 결과 (교차검증, 2026-11-04)

| 검사 | 탐지율 (95% CI) | 정상 보류 (95% CI) | 메모 |
| --- | --- | --- | --- |
| 엔진 문구 규칙만 (D6-39) | 2.7% (1.0–6.7%) | 2.7% (1.0–6.7%) | 규칙이 영어 문구뿐이라 한국어 공격을 거의 못 잡고, `.env`·`id_rsa`·`~/.aws`를 말하는 정상 보안 안내 4건을 잡았습니다 |
| Horizon 분류기 | **45.3%** (37.6–53.3%) | 2.7% (1.0–6.7%) | Docker에서 측정(이 PC는 onnxruntime이 뜨지 않음). 겹마다 고른 기준값 0.73–0.93. 직접 지시(87%)·인코딩(83%)·한영 혼합(89%)은 잘 잡고, 사용자에게 숨기기(13%)·다른 도구 가로채기(20%)는 약합니다 |
| 분류기 + 규칙 | 14.7% | 2.7% | 규칙의 오탐(`.env` 안내 등)이 1.0점으로 들어가 기준값이 1.0으로 올라가면서 오히려 낮아졌습니다. 한국어에서는 분류기만 쓰는 편이 낫습니다 |

### 탐지율 99% 검토 (정상 보류 2% 이하에서)

측정이 끝나기 전의 검토입니다. 효과는 분류기 결과를 본 뒤 같은 교차검증으로 확인합니다.

| 방법 | 기대 | 비용·위험 |
| --- | --- | --- |
| 1. 분류기 기준값을 2% 기준으로 다시 고르기 | 모델 카드의 0.5 대신 데이터로 고른 값 | 낮음. 이미 `cv.py`로 가능 |
| 2. 입력 정리: 한글 음절 사이 공백·점 제거, 자모 합치기, 보이지 않는 문자·다른 문자 체계 숫자 제거, base64·16진수 풀어 함께 검사 | 난독화·인코딩 공격(이 세트 6개 문장, 18개)을 분류기와 규칙이 읽을 수 있게 함 | 낮음. 결정적 처리라 판정은 그대로 B |
| 3. 한국어 문구 규칙 추가 ("무시하고", "알리지 마", "숨은 참조", 외부 주소로 보내기 등) | 직접 지시형을 확실히 잡음 | 같은 작성자가 데이터와 규칙을 함께 쓰므로 과적합 위험. 규칙은 학습 겹에서만 보고 만들고, 새 데이터로 다시 확인해야 함. "앞에 쓴 내용은 무시하고" 같은 정상 요청과 충돌 |
| 4. 한국어를 영어로 옮긴 뒤 분류 | 영어 위주로 학습된 모델이면 도움 | LLM 의존이 생기고, 번역이 공격 문장을 순화할 수 있음 |
| 5. 설명문 LLM 검사(D6-44)와 묶기 | 의미로 판단하므로 바꿔 말한 공격에 강함 | 영어 평가에서 정상 보류 12%로 기준 초과. 한국어 평가 없음 |
| 6. 한국어 데이터로 분류기 추가 학습 | 가장 큰 개선 가능성 | 수천 개 이상의 데이터와 학습 환경 필요. 평가 세트와 섞이면 결과를 믿을 수 없음 |

- **99%에 대해:** 공격 150개로는 99%(1개 이하 놓침)를 관측해도 95% 신뢰 하한이 약 96%라서 "99%"를 확인할 수 없습니다. 99%를 확인하려면 공격 문장이 수백 개 더 필요합니다. 또 정해 둔 세트에서의 수치는 공격자가 검사기를 보고 바꿔 쓰는 공격(적응형 공격)에서의 성능을 뜻하지 않습니다.
- **순서 (2026-11-04 사용자 결정):** 분류기 측정 → 1 → 2. 3(한국어 규칙)과 4–6은 나중으로 미룹니다. 도구 설명문은 대부분 영어이고, 응답 속 한국어 공격은 언어와 무관한 M4 오염 표시·외부 전송 차단이 막으며 B 응답 검사는 기록만 하기 때문입니다. 운영 기록에서 한국어 공격 시도가 보이면 다시 엽니다. 탐지율을 올릴 여지는 영어 설명문 규칙(MCPTox 42%)이 더 큽니다.

### 영어 설명문: 단계식 판정 (MCPTox, D6-51·D6-53)

문구 규칙 + 구조 신호 다음에 분류기를 붙여 같은 개발/시험 절반으로 평가했습니다(`b_text/eval_structure.py --classifier`, Docker).

| | 시험 탐지 | 시험 정상 보류 |
| --- | --- | --- |
| 문구 규칙 + 구조 신호 | 82.1% | 0.47% |
| **+ 분류기 (기준값 0.86, 개발 절반에서 고름)** | **95.7%** | **1.18%** |
| + 남은 것 중 분류기 점수 0.01–0.86인 것만 LLM에 물음 (qwen2.5-coder:7b, 절반당 40개 표본) | 95.7% | 1.18% |

LLM 단계는 표본 79개 중 12개를 수상하다고 했지만, 개발 절반에서 정상 보류 2% 이하를 지키는 조합을 고르면 LLM 판정을 사실상 쓰지 않는 쪽(점수 0.5 이상만 LLM 판정 인정)이 뽑혀 탐지율이 늘지 않았습니다. 그래서 LLM 검사(D6-44)는 계속 선택·기본 꺼짐으로 둡니다. 표본 평가이므로 전체 회색 구간(644개)에서는 결과가 다를 수 있습니다.

### 자원과 기본값 (D6-53)

Docker(CPU 20코어)에서 잰 값: 모델 읽기 17초, 메모리 약 530MB 증가(프로세스 543MB), 문장당 중앙값 16ms·95번째 25ms. 사용자 기준(자원을 크게 쓰지 않으면 켬)에 따라 **배포 compose에서는 기본으로 켭니다**(`MCP_GUARD_WITH_CLASSIFIER=0`으로 끔). 기준값 기본은 0.86입니다(`--b-threshold`, `MCP_GUARD_B_THRESHOLD`). 개발용 서버는 런타임이 없을 수 있어 계속 `--b-classifier`로 켭니다. 첫 실행 때 Hugging Face에서 가중치를 받으므로 인터넷이 필요합니다.

## 한계

- 한국어 평가 데이터 v2(300개)는 사람 검토 전입니다. 분류기 측정은 Docker에서 했고, 이 Windows PC에서는 onnxruntime이 뜨지 않습니다.
- 분류기 오류는 `B_CLASSIFIER_UNAVAILABLE` 신호로 기록되고 등록 도구는 `review`로 보냅니다. 응답은 변경하지 않습니다.
- 모델은 보조 신호입니다. A 검사나 4단계 통제를 대체하지 않습니다.
- B 점수는 판정을 review까지만 올립니다. block은 A 결정만 냅니다.
